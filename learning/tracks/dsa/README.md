# Track 2 — Data Structures & Algorithms (DSA)

> **This is the single most important track for passing a hard coding interview.**
> Almost every question at top companies (and the foundation of competitive programming
> and quant dev) is a DSA problem.

**Prerequisite:** Python fundamentals (Track 1). You should be comfortable with lists,
loops, functions, and dictionaries before starting here.

**Language:** We'll learn DSA in **Python first** (cleanest syntax to focus on ideas),
then re-practice the same patterns in **C++** later for speed.

---

## Why it matters for your goals
- **Interviews:** This *is* the interview at most companies.
- **Competitive programming:** Codeforces problems are DSA under time pressure.
- **Quant dev:** Quant firms test DSA heavily, often harder than big tech.

---

## Syllabus (in order)

### Part A — Foundations
1. **Big-O notation** — how to measure if your code is fast enough (the language of interviews)
2. **Arrays & strings** — the workhorses; in-place tricks
3. **Hash maps & hash sets** — *the* most useful interview tool; O(1) lookups
4. **Two pointers** — pair/triplet problems, in-place reversal
5. **Sliding window** — substring/subarray problems

### Part B — Linear structures
6. **Stacks** — LIFO; matching parentheses, monotonic stacks
7. **Queues & deques** — FIFO; BFS, sliding-window-maximum
8. **Linked lists** — pointers, reversal, cycle detection (fast/slow pointers)

### Part C — Recursion & trees
9. **Recursion** — the mental model; base cases; the call stack
10. **Binary trees** — traversals (inorder/preorder/postorder), DFS/BFS
11. **Binary search trees (BST)** — ordered data, O(log n) operations
12. **Heaps / priority queues** — top-K problems, scheduling
13. **Tries** — prefix trees for word problems

### Part D — Algorithms & paradigms
14. **Binary search** — on arrays *and* on the answer space
15. **Sorting** — merge sort, quick sort, and when to just use `sorted()`
16. **Graphs** — representations, BFS, DFS, topological sort
17. **Backtracking** — permutations, combinations, N-queens, sudoku
18. **Dynamic programming (DP)** — the big one; memoization → tabulation
19. **Greedy algorithms** — when local choices give global optima
20. **Bit manipulation** — XOR tricks, masks

---

## How to practice (this matters as much as the topics)
- Learn a pattern here, then solve **3–5 problems** on it before moving on.
- Use the **"understand → plan → code → test"** loop on every problem. Never code first.
- Re-solve problems you struggled with a week later (spaced repetition).
